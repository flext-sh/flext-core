This document is a **manual planning contract**, not a generated API reference and not
proof that the listed APIs exist today. Current public exports remain governed by
`src/flext_core/__init__.py` until the 0.13 implementation is approved.

For current 0.12 usage, read [Using flext-core 0.12](../guides/using-flext-core.md).
The future release gate is Bead `flext-ik359`; this document neither changes
0.12 exports nor authorizes migration or release activation.

## Public target

`from flext_core import c, t, p, m, u, core`

No long `Flext*` names and no operational aliases (`r`, `e`, `x`, `h`, `d`, `s`) are
part of the target public API. Removed names must be replaced by one of:

- an existing public facade (`c`, `t`, `p`, `m`, `u`);
- a retained implementation exposed through `core`;
- a newly specified contract with owner and migration path;
- removal with no replacement, after caller proof.

The proposed `core` is a typed lazy module namespace. It is not the current
`FlextCore` singleton and must not act as a service locator. Applications own
`api.py`, instances, ports and runtime objects.

## Dependency injection flow

1. Transport validates input once.
2. The application `api.py` constructs adapters and port-bearing services.
3. Services receive ports as `t.Port[p.X]` and settings as explicit values.
4. Services return `Result` values without re-parsing or copying payloads.
5. Transport serializes or renders output once.

No service may use a global singleton, string lookup, reflection or ambient container to
obtain dependencies. `fetch_global()` remains only for port-free services and must not be
used as a composition root.

## Settings and configuration

Settings and configuration bases belong to core. Configured objects and reload
semantics belong to the consumer:

- ai-hub requires strict YAML, deep merge, transform and reload without stale
  imported references.
- OUD requires caller-supplied `config=` and `runtime=`, LDAP/LDIF settings inheritance,
  secret preservation and no JSON round-trip masking.
- Core must specify whether reload updates or replaces an object, how services observe
  it and what happens on validation failure.

## Consumer migration matrix

| Consumer | Receives | Must change |
| --- | --- | --- |
| `flext-cli` | Service base, Result, CLI routes, config/settings bases | Specialize `core.Service`; migrate operation discovery; preserve CLI options and `--help` |
| `flext-infra` | Service base, Result, validation, registry/dispatcher | Update imports, templates, bootstrap and exports together |
| `flext-tests` | `tm`, fixtures, session runtime | Migrate plugin, alias binder, case contract and templates |
| `flext-ldap` / `flext-ldif` | Models, ports, Result, registry | Keep injected registry and connection payloads |
| `flext-meltano` / connectors | Thin service base, Result, models | Replace global LDAP collaborator with explicit wiring |
| `ai-hub` | Service MRO, settings/config, Pydantic presets, Result, CLI | Resolve infra runtime inheritance and `services/js_tree.py` boundary |
| `algar-oud-mig` | Service MRO, LDAP/LDIF settings, Result, CLI | Preserve caller isolation, D12 authorization and package proof |

## Non-goals

- No code migration, codemod, lock update, merge, installation or activation is
  authorized by this document.
- No generated `__init__.py`, API reference or module page is edited manually.
- No ADR is considered implemented solely because its target is documented here.
- No consumer is migrated before the contracts and support documents are approved.
