# YAGNI necessity procedure

## Necessity gate

For every proposed or retained surface require all three:

1. an approved current acceptance criterion or invariant;
2. a real current consumer;
3. a reachable supported runtime or build path.

Record the exact evidence, owner candidates, lifetime, and keep/reduce/reuse/delete
decision. Read definitions, callers, registrations, dynamic loaders, generators,
manifests, and public construction roots. A test for speculative code, one absent
search result, incomplete telemetry, future scale, symmetry, possible reuse, or
framework fashion is not current need.

Equal-valued environment variables, settings, parameters, and arguments that
repeat a typed canonical default also fail the necessity gate. Keep only the
owner default and supported non-default overrides.

## Atomic removal

1. Protect every supported behavior and its failure boundary.
2. Select the unique authority through `ssot`, remove speculation there, and
   rewire real consumers to the smallest existing capability.
3. Apply `solid` only to necessary boundaries, `dry` only to proven structural
   work, and `simplify` to each changed unit.
4. Remove future modes, flags, interfaces, registries, adapters, dependencies,
   config, tests, fixtures, examples, docs, shims, aliases, fallback, and old paths
   in the same change.
5. Search for the removed identity and alternate construction paths; old/new
   surfaces never coexist.

Run the real public runtime for retained behavior and removed/unsupported input,
then affected native gates. A removed request fails causally without rerouting or
effects. Report every retained requirement/consumer/runtime, deleted surface,
owner decision, code and dependencies removed, runtime/gates, zero effects, and
zero residue.
